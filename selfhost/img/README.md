# Image gateway (Imgix replacement)

Upstream Campsite served every uploaded file (images, videos, downloads) through Imgix, an image CDN fed from S3. This fork serves them from `img.camp.<domain>` instead:

```
browser -> Cloudflare -> Caddy gateway (gateway.caddy) -> imgproxy -> S3 (MinIO locally)
```

The URLs the code builds do not change: `IMGIX_URL + "/" + <s3 key> + "?" + <imgix params>` (Ruby `build_imgix_url`, web `` `${IMGIX_DOMAIN}/${path}` ``). The gateway translates the Imgix query parameters into imgproxy processing options. It is configuration only (a Caddy file), no extra service.

## Files

| File | Purpose |
|---|---|
| `gateway.caddy` | The translation. Import it inside a Caddy site block. Needs `IMGPROXY_UPSTREAM` (for example `imgproxy:8080`). |
| `Caddyfile` | Standalone gateway on `:8080` that imports `gateway.caddy`. |
| `compose.test.yaml` | Throwaway MinIO, imgproxy and gateway for `test.sh`. |
| `test.sh` | Brings up the test stack, seeds `fixtures/`, runs the curl checks, tears down. |
| `fixtures/` | A 200x150 PNG and a 2 second 160x120 MP4. |

## Parameters used by the code

Found with the grep in the plan plus a read of every `build_imgix_url`, `build_imgix_video_url` and `fallback_avatar` call (`api/app`) and every `IMGIX_DOMAIN` or `?fm=` use (`apps/web`, `packages`).

| Imgix parameter | Where | imgproxy translation | Notes |
|---|---|---|---|
| `w=N` | avatars, image_urls, attachments, comments | `w:N` | Integers only. |
| `h=N` | avatars, gif thumbnails, comments | `h:N` | Integers only. |
| `fit=crop` | avatars, message thread avatars | `rt:fill` | Without `fit`, imgproxy's default `rt:fit` (fit inside the box) matches Imgix's default `clip`. |
| `dpr=N` | image_urls, attachments | `dpr:N` | imgproxy never enlarges past the source size; Imgix could. |
| `q=N` | image_urls | `q:N` | |
| `auto=compress,format` | image_urls, attachments, comments | ignored by the gateway | `format` is handled by imgproxy with `IMGPROXY_AUTO_WEBP=true` (WebP when the browser sends `Accept: image/webp`, with `Vary: Accept`). `compress` is imgproxy's default quality (80). |
| `rect=x,y,w,h` | comment canvas previews | `c:w:h:nowe:x:y` | Crop before resize, same as Imgix. |
| `frame=1` | GIF thumbnails | ignored | imgproxy keeps only the first frame when it processes an animated image (`IMGPROXY_MAX_ANIMATION_FRAMES` defaults to 1), which is what `frame=1` asked for. Verified with a 3 frame GIF. |
| `dl=` (and `dl=<name>`) | `Attachment#download_url` | `raw:1/att:1` | Original bytes with `Content-Disposition: attachment`. The filename is the key's basename (the code always sends an empty `dl`); a non-empty `dl` name is ignored. |
| none | `Attachment#url`, videos, documents, SRT transcripts, static files | `raw:1` | Original bytes, streamed from S3, with `Accept-Ranges: bytes` and `206` for range requests (video seeking). |

### Unsupported parameters and their fallback

Any request whose parameters translate to nothing (only unsupported or ignored parameters) is served as the original file (`raw:1`).

| Imgix parameter | Where | Fallback | Effect |
|---|---|---|---|
| `fm=mp4` | web: `GifAttachment` (notes and threads), `LightboxAttachmentRenderer`, `GalleryThumbnail`, `MediaGallery/Pagination` | original GIF | GIF to MP4 conversion is an imgproxy Pro feature. These components put the URL in a `<video>`, which cannot play a GIF, so animated GIFs there do not play until the web renders GIFs with `<img>` when the image host is not Imgix. |
| `video-generate=thumbnail`, `video-thumbnail-time` | `ImgixVideoThumbnailUrls` (`IMGIX_VIDEO_URL`) | not translated; with `w`/`dpr` imgproxy returns an error, without them the original video | Video thumbnails are an imgproxy Pro feature. Only used when an attachment has `imgix_video_file_path` (the web never sets it) and for 100ms call recordings (calls are not configured). |
| `blend-color=RRGGBB` | `fallback_avatar` (letter avatars) | ignored, resize still applied | Imgix tinted the grey letter avatars from `default_avatars/` (opaque, so imgproxy's `bg:` would not help). Fallback avatars show in grey. |
| `dl=<name>` | web mock data only | original filename | |
| non-integer `w`/`h` (Imgix fractions) | not used | parameter dropped | |

Known limitations of the translation:

- An S3 key that contains `@` would be read by imgproxy as a format suffix. Upload keys are generated by the API (`o/<org>/p/<uuid>.<ext>`), so this does not happen in practice.
- A transform parameter on a file imgproxy cannot decode (for example PDF previews, an imgproxy Pro feature) returns an imgproxy error instead of the Imgix rendering. The code only adds transform parameters to images and image previews.

## Choice and why

Config only: every parameter the code uses maps to a single imgproxy option, and imgproxy's `raw:1` already streams originals with range support and `att:1` sets the download header, so no custom service is needed. Caddy is already the edge proxy of the stack, so the gateway adds no new kind of component. The translation is a set of Caddy `map` directives (one per parameter) whose outputs are concatenated into the imgproxy path. imgproxy is never exposed directly, so it runs with unsigned (`/insecure/`) URLs; `IMGPROXY_BASE_URL` and `IMGPROXY_ALLOWED_SOURCES` pin every request to the media bucket.

## Settings

imgproxy:

| Variable | Local (MinIO) | AWS |
|---|---|---|
| `IMGPROXY_USE_S3` | `true` | `true` |
| `IMGPROXY_S3_ENDPOINT` | `http://minio:9000` | unset |
| `IMGPROXY_S3_ENDPOINT_USES_PATH_STYLE` | `true` | unset |
| `IMGPROXY_S3_REGION` | `us-east-1` | the bucket's region |
| `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` | MinIO user | unset: imgproxy uses the instance role |
| `IMGPROXY_BASE_URL` | `s3://<bucket>/` | `s3://<bucket>/` |
| `IMGPROXY_ALLOWED_SOURCES` | `s3://<bucket>/` | `s3://<bucket>/` |
| `IMGPROXY_AUTO_WEBP` | `true` | `true` |

`IMGPROXY_ENABLE_DEBUG_HEADERS` is set only in `compose.test.yaml`.

Gateway: `IMGPROXY_UPSTREAM` (for example `imgproxy:8080`).

API (ENV first, Rails credentials as fallback):

| Variable | Value | Used for |
|---|---|---|
| `IMGIX_URL` | `https://img.camp.<domain>` | every `build_imgix_url`, the default project cover, the web push icon |
| `IMGIX_VIDEO_URL` | `https://img.camp.<domain>` | video thumbnails (unsupported, see above) |
| `IMGIX_FOLDER_URL` | `https://api.camp.<domain>` | note thumbnails and post note Open Graph images in production. Upstream this was an Imgix web folder source in front of the API; the API serves these routes itself. |

Web: `NEXT_PUBLIC_IMGIX_DOMAIN=https://img.camp.<domain>`.

`ImgixAddAssetJob` (registers 100ms recordings with Imgix) does nothing when no Imgix API key is configured. There are no Imgix purge calls in the code.

Static files the code references by path (`static/avatars/*.png`, `static/apple-touch-icon-512.png`, `project-covers/*.png`) must be present in the bucket. The letter avatars are in `default_avatars/`.

## Test

```
selfhost/img/test.sh
```

Needs Docker (compose v2) and curl 7.75 or later (`--aws-sigv4`). `MINIO_IMAGE` overrides the MinIO image (default `pgsty/minio:latest`, a maintained build of the MinIO server; the official `minio/minio` image is no longer pulled from Docker Hub here). Host ports default to 19000 (MinIO) and 18080 (gateway) on 127.0.0.1 and can be changed with `IMG_TEST_MINIO_PORT` and `IMG_TEST_GATEWAY_PORT`.
